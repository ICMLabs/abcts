## THE NEXT UNIT: `tune.topText` AND `tune.bottomText`

They are the two the field-source-range plumbing was supposed to unblock and they are the two
still absent — and the reason is worth knowing before you start: **they are abcjs's
INTERMEDIATE row list, not its result.** `new TopText(metaText, metaTextInfo, formatting,
lines, width, isPrint, paddingLeft, spacing, shouldAddClasses, getTextSize)` builds
`this.rows`, an array interleaving `{move: n}` rows with
`{left, text, font, klass, anchor, startChar, endChar, absElemType, name}` rows
(`write/creation/elements/top-text.js`, `bottom-text.js`).

**WE ALREADY COMPUTE BOTH HALVES.** `topTextBlock` returns `{ texts, lines, height, advances }`
— `advances` IS the `{move}` sequence, spent in order by the page's cursor, and `texts` carries
`dataName`, `x`, `y`, `size`, the face, the box and now `selectable` (which is
`absElemType` + `startChar`/`endChar` + `name`). So this is a PROJECTION exactly like
`tune.lines`: build it on read from the layout, do not retain a `Layout` (see the trap below),
and do not invent a second copy of the row list.

**BUILD THE ORACLE FIRST, as every closed arc here did.** `/tmp/gp/mti.js` is the template:
walk `abcjs.renderAbc(slots, abc, {staffwidth: 670})[i].topText.rows` over both corpora and
write `tests/corpus-toptext/golden.json`. It needs a RENDER, not a parse, so it needs
`dump-svg.js`'s `getBBox` stub — lift it from `scripts/harvest-abcjs-selection.mjs:157-190`,
which already has it working under jsdom.

⚠️ **AND ITS `y` WILL DISAGREE WITH A BROWSER ON 46 TEXT ELEMENTS** — `dump-svg.js`'s
`fontHeights` has SEVEN entries and anything else falls to `size + 2`. `GOLDEN_TEXT_HEIGHTS`
reproduces that fallback ON PURPOSE, so we match the goldens; state it in the harvester's
header the way `harvest-abcjs-selection.mjs` does rather than discovering it twice.

### AND THE BLOCKER IS THREE PLUMBING FACTS, NOT A RULE — DO THEM IN THIS ORDER

1. **THE INTERLEAVING IS LOST.** `topTextBlock` returns `{texts, lines, height, advances}` —
   two parallel arrays whose ORDER against each other is not recorded. `PlacedText.advanceAt`
   is exactly the missing index and it already exists: `nonMusicBlock` stamps it,
   `topTextBlock` does not. Stamping `advanceAt: advances.length` at each of its six pushes
   makes the interleave mechanical — emit `advances[0…advanceAt-1]`, then the row — and
   changes no output, so the check is the one this repo trusts: suite green and NO BASELINE
   MOVED.
2. **A ROW'S FONT TYPE NAME IS NOT CARRIED.** `PlacedText` holds `size`, `face`, `bold` and
   `italic` — not `"titlefont"`. `topTextBlock` knows the type at every push, so this is a
   field to add rather than a value to derive.
3. **AND THE `Layout` DOES NOT EXPOSE THE BLOCK AT ALL.** `doc.topText` is set only for a tune
   with NO music; otherwise the block's rows are folded into the first system's texts with
   `nonMusicIndex === undefined`, and `advances` never reaches the doc. `RenderDoc` needs to
   carry the ordered row list — which is also the honest shape, since it is what `nonMusic`
   walks.

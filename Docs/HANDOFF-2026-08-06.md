## WHERE TO START

### 1. `transpose-output-03` and `-04`, 0.93 — the top of the table

A matched pair: `dx` 0.9 with `ox` −0.1, so a SPREAD and almost no prefix shift, and `-04`
also carries `oy` −0.8. Both are `transpose-output` fixtures with no directives at all,
which is unusual — nearly everything else left on the table has one.

The cheapest first move is the one that settled finding 104: dump abcjs's per-element
`w/minspacing/extraw` with the harness and diff against ours. If every width matches, the
difference is in the solve or the spring; if one does not, it is that element.

### 2. TWO RULES READ BUT NOT CHECKED

Both surfaced while reading for findings 104–105, neither is exercised by anything currently
red, and both are cheap to test:

- **A rest exactly filling a measure becomes a WHOLE rest** —
  `if (this.measureLength === duration && type !== 'invisible' && type !== 'spacer' &&
  type.indexOf('multimeasure') < 0) elem.rest.type = 'whole'` (`abstract-engraver.js:812`).
- **`%%barnumbers 0` puts the number on the STAFF rather than a barline** —
  `abc_parse_music.js:1036`, reaching `addMeasureNumber(barNumber, clef)`. That is the path
  where `abselem.isClef` shifts the number right by half its width and the `vert = 13.5`
  branch can fire; on a barline it never can.

### 3. THE PROBE PATTERN, worth reusing verbatim

Every measurement in this checkpoint came from a throwaway `tests/zz-probe.test.ts` that
imports `renderAbc` and `absolutePixels`, walks both engines' items and writes to `/tmp`.
Fifteen lines, deleted after use. Pair it with the abcjs harness and you can ask the same
question of both engines in one turn.

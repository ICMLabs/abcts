## ⭐ THE FINDING OF THIS SESSION, AND IT IS ABOUT WHAT A GATE CAN SEE

**FIVE of the rules closed here are defects on the DEFAULT path that no default-path gate could
see.** `svg-bytes` is 0 of 691, both browser gates are 0 of 685, and all of these were live:

  1. A **rest's width** ignored the voice `scale=` — a rest reaches `createNoteHead` like any
     head, so `getSymbolWidth(c) * scale` applies to it too.
  2. A **chord's width** was read from the chord-level glyph, where `abselem.w` is the max over
     its heads AS ADDED — so a per-pitch `!style=x!` on the MIDDLE head widens the element.
  3. Our **collision pass grouped simultaneity by `x`** where abcjs groups by **TIME**.
  4. An **ending's room was charged to every voice**, where abcjs charges `voicenumber === 0`.
  5. A **boxed row's rect was measured at the wrong x** corpus-wide.

⭐ **AND THE REASON IS ONE SENTENCE: AN OPTION IS A RESERVE MAGNIFIER.** A width only reaches
the page when it beats the elastic gap beside it; `minspacing` is only a floor on a cursor every
voice shares. Change which reserve wins — `minPadding: 40`, or a second layout algorithm — and
the masked rule surfaces. **A RESERVE ALWAYS MASKED BY A BIGGER ONE IS A RULE NO GATE CAN SEE**,
and this is how you unmask it.

⭐⭐ **A SECOND ALGORITHM REVEALS EVERY COINCIDENCE THE FIRST ONE PAID FOR.** (3) and (4) were
*correct outputs* for as long as the spring solve was the only layout. The grid did not break
them; it revealed them. Both fixes are on the default path and `svg-bytes` did not move.

## ⚠️ WHAT IS LEFT — two representations, four last digits, and three decisions

**Two structural items. Each is a REPRESENTATION, not an arithmetic slip, which is why neither
was bolted onto the end of this session:**

- **A rule's EDGE, not its CENTRE** — closes `timeBasedLayout`'s last row. abcjs stores a
  bar/stem rule's edge and `printStem` writes `roundNumber(x)` then `roundNumber(x + dx)`; we
  store the CENTRE and recover `centre - half`. Both engines place `rests-and-bars-tune13`'s bar
  at **exactly 119.955** and round it opposite ways, because our recovered edge is
  `119.95500000000001`. ⚠️ The engine already documents this asymmetry under `lineThickness` —
  "abcjs leaves `printStem`'s `x` alone and grows `dx`; ours places a stem by its CENTRE" — so
  the fix belongs with that note, and it touches every bar and every stem.
- **The page WIDTH primitive** — closes the ULP half of `print` ×2. abcjs keeps the MUSIC width
  and adds the margins once, at `setPaperSize`, LEFT THEN RIGHT. We keep the summed page and
  subtract the sides back out, so `pageSides()` sums the margins first and abcjs's `(a+b)+c`
  becomes `a+(b+c)`: `1037.3333333333333` against `…335`, which at print's 0.75 is 778 against
  778.0000000000001. ⚠️ 691 goldens rest on the current arithmetic.

**Four located and small**: the print **page-cursor** sum (23.54px on
`visual-options-01-fonts` — many small top-block advance errors that CANCEL in the rows' own ys
and not in the cursor, and removing any ONE of eighteen `%%…font` directives takes the delta to
zero); one nested-tspan bbox (`scale 0.8`, 1/64 on box 3 of 4); `add_classes`'s ending counter
(a volta wants the `measureElement` a TRIPLET already carries, and the derivation breaks where

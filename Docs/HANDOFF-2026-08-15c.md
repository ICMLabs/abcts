## THE TWO TRAPS THIS SESSION PAID FOR

### AN UNBRACED `if` TURNS A PROBE INTO A BEHAVIOUR CHANGE

Four probes in the scratchpad copy of abcjs sat directly under an unbraced `if` and had
STOLEN its body — three of them on the very `foundKey` guards they were added to measure:

    if (result.foundKey && tuneBuilder.hasBeginMusic() && multilineVars.keywarn !== false)
        if (process.env.ABCJS_KEY) console.error('FIXKEY site2 clef', …);
        tuneBuilder.appendStartingElement('key', …);          // ← NO LONGER GUARDED

All four are braced and a sweep reports zero. **Cost: nothing, and that is knowable** —
every golden in both corpora is generated from the VENDORED tree by `dump-svg.js`, never
from the scratchpad. `/tmp/gp/twin.js` renders every fixture through BOTH trees and diffs
(**221 of 221 identical**) — and, checked the way this branch checks things, that probe
CANNOT see this particular defect: re-breaking the brace leaves all 221 identical, because
no fixture in either corpus reaches those guards' false arms.

**Brace the `if`, and run `twin.js` after instrumenting.**

### A NOTE THAT NAMES A CAUSE IS THE REASON A ROW STOPS BEING READ — twice more

- `content-parity` excluded `escaped-percent` under a paragraph reasoning "our target is
  6.6.3". **The target moved to 6.7.0 the same day that note was written**, so a fixture
  whose entire purpose is the `\%` rule sat out for a week with every note after the escape
  silently dropped. **When a note reasons from "our target is X", check X.**
- `strTranspose`'s last open row was filed as "our parser drops a chord before a barline",
  measured from `Measure.openingBarlineChord` being `undefined` — and
  `closingBarlineChord` sits right beside it in the model. **Two fields, one checked.**

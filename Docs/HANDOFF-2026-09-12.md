## ⭐ THE METHOD — and the one it caught was MINE

RECORDED AN HOUR AGO.** The ending fix below excluded `voltaOnOpeningBar` with a reason I
wrote into the code: such an ending draws on the new system "because that is where its bar
is". Four rungs later, on `[|]1`/`[|]2`, abcjs put both brackets at x 415 — the PREVIOUS
system's right edge — exactly as a closing-bar ending. **The exclusion is disproved and the
comment now says so.** The repo's standing trap fired on the session that was quoting it.

**⭐ DIFFERENCE THE ELEMENT KINDS, NOT THE BYTES.** A first-differing byte offset says only

`tagName:data-name` counts says **which element is MISSING** — and that turned an
undifferentiated 48 into 16 + 7 + 6 + 5 + 2 + 4 + 2 in one sweep. It is the instrument that
made the map, and it costs ten lines.

**⭐ BUILD THE PREDICATE AGAINST THE REFERENCE, NOT AGAINST YOUR OWN TYPE.** The meter rule
needed "is there a non-music row before the music". Rather than enumerate our fields and
hope, both sides were counted over all 685: abcjs's `tune.lines.findIndex(l => l.staff) > 0`
names 41, and `titles.length > 1 || textAbove.length > 0 || newPage != null` names **the
same 41**, with no fixture on either side of the disagreement. ⚠️ `newPage` is a NUMBER —

**⚠️ AND PROVE THE TEST FIRES ON EACH HALF SEPARATELY.** Both fixes have two halves and each

## 🔬 WHAT LANDED

**1. THE METER GOES WITH A NON-MUSIC FIRST ROW — 59 → 53.**

    if (keys[k] === "meter" && action.line !== 0) skip = true;      // wrap_lines.js:43

⚠️ **`action.line` IS THE OUTPUT LINE INDEX OVER THE WHOLE TUNE AND IT COUNTS THE NON-MUSIC
ROWS.** `findLineBreaks` advances one `outputLine` for a subtitle, a `%%text`, a `%%sep` or a
`%%newpage` exactly as for a staff line (`:150-153`), so a tune opening with a subtitle has
its music on line 1 and loses the meter on **EVERY** system, the first included. The line
reads as though only the REPRINTS go, and this repo had ported it that way: `i === 0` in
`lines.ts` and `systemIndex === 0` in `layout.ts` are the first MEASURE and first SYSTEM,
which is abcjs's line 0 only when nothing precedes the music. Both the ink AND `tune.lines`
were wrong; `Score.wrapDroppedMeter` is the one fact, read at two sites.

**2. AN ENDING OPENS ON THE SYSTEM WHOSE BARLINE DECLARES IT — 53 → 48.** abcjs opens the
`EndingElem` where it processes the BAR (`abstract-engraver.js:1034-1042`), and a break at
that bar leaves it the LAST element of the line it CLOSES. So the ending opens there, hook
at the line's right edge WITH its number, and the next line gets a fresh
`EndingElem("", null, null)` from `createABCVoice` (`:230-233`) — no hook, no number.
`|:CDEF|1GABc:|3cdef|]` is `226.78/1`, `415/3`, `222.76/` in both engines now; ours drew ONE
bracket, numbered, on the wrong system.

⚠️ **AND IT WAS NOT A WRAP DEFECT.** `%%barsperstaff 2` reproduces it on the same tune with
no wrap at all, and no golden covers that path. Fixed for both.

🆕 **AND `%%barsperstaff` HAS ITS OWN SPLITTING DEFECT, NOW NAMED AND NOT FIXED.** abcjs puts
`|:CDEF|` ALONE on line 1 under `%%barsperstaff 2` where we put two measures — because abcjs
counts BAR ELEMENTS there too and `|:CDEF|` is two of them, which is exactly the rule the
wrap learned last session. `wrapMusicLines` (`parser.ts:3556`) counts measures. **No gate
renders it**, which is why it has never been seen.

**3. A DISSOLVED LINE BREAK RE-EMITS THE LINE'S STAFF KEY, METER AND CLEF — 48 → 42.**
`deline` runs BEFORE `findLineBreaks`, and merging a line turns that line's STAFF property
into a voice element it unshifts onto the voice with `startChar: -1`
(`data/deline-tune.js:23-39`, `:126-151`). The wrap dissolves the source break and BOTH
survive: the previous line's WARNING, which carries the source range, and this injected
copy, which carries none — `keySignature@26 keySignature@-1`.

⚠️ **THE GUARD IS `objEqual` AGAINST THE PREVIOUS LINE'S HEAD, NOT "THIS MEASURE HAS A
CHANGE",** and the two rungs that settle it fall opposite ways: a RESTATED `K:C` is a change
that injects nothing, and an INLINE `[K:G]` on the line before injects although the next
measure carries no change at all — `currentKey` tracks the STAFF key alone.

⚠️ **AND `startChar: -1` SORTS TO THE FRONT OF THE LINE AND IS THEN DROPPED.** `lines.ts`'s
`stream` orders by `startChar`, so the injected element landed ahead of every note;
`hoistLeadingStaffFields` found a staff field before the first note or bar, tried to move it
to the line above, and — nothing above holding music — **dropped it**, which that function
says in so many words. It was in `out` and absent from `tune.lines`, silently. A `sortAt`
pin holds it. **Two surfaces again** — the ink and `tune.lines`, as the meter rule needed.

**5. BAR NUMBERS ARE RENUMBERED FROM 1, LOSING `%%setbarnb` AND THE FREQUENCY — 41 → 34.**
Not a lost label, a different numbering. `addLineBreaks` counts BAR ELEMENTS from 1 and
assigns unconditionally — no `% barNumbers` test survives the wrap — hangs the running value
on each output line's staff, and deletes the number on the bar that ENDS a line
(`wrap_lines.js:37-39`, `:78-88`). Measured on eight bars: `%%barnumbers 5` + `%%setbarnb 24`
draws `25 30` unwrapped and `1 2 3 4 5 6 7 8` wrapped. We carried the parser's numbers across.

⚠️ **AND THE GATE IS THAT THE DIRECTIVE APPEARED, NOT THAT IT DREW ANYTHING.** `%%barnumbers
50` fires on no bar of that tune and `%%barnumbers 0` numbers the CLEF rather than a barline;
both draw nothing unwrapped and every bar wrapped. So "some measure carries a number" is not
a usable proxy — `Score.barNumbersDirective` exists because the proxy was MEASURED and
failed, not because it looked unsafe.

⚠️ **AND `score` INSIDE THE VOICE MAP IS THE INPUT SCORE.** The head number reads
`wrapDroppedMeter`, which is added to the RETURNED score — so it was `undefined` where the
walk read it and every head number silently failed to draw. Hoisted above the walk.

⚠️ **AND NOTHING IN THIS REPO COULD SEE IT.** The six fixtures that show a lost tempo were

⭐ **THE RULE THIS ADDS: WHEN YOU NARROW A SHARED FLAG, GREP ITS USES FIRST.** One `grep -n
withMeter` would have cost ten seconds and shown `:13402`.

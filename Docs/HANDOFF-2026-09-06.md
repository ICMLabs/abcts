those notes had the CAUSE right and the SIZE wrong**, which is the more expensive mistake: a
wrong cause gets tested and falls over, a wrong size stops the work being attempted at all.

1. **The sequencer's volume reset** (`ABCJS-DEBT.md` §3b.5, two ports written and reverted).
   `currentVolume` (`abc_midi_sequencer.js:223`) and `stressBeat1/Down/Up`
   (`abc_midi_flattener.js:76-79`) are **two variables in two files** and `flatten.ts` had
   modelled them as one. The sequencer's restarts at every (line, staff, voice); the
   flattener's is reset once per `flatten()` and moves only when an `el_type: 'beat'` row
   reaches it, which only a hairpin step or a dynamic pushes. That is the whole
   reconciliation — a voice with neither carries the previous voice's table (the
   `!mp!`-across-voices finding) while a hairpin crossing a line steps from the default
   again. Both reverted attempts reset the FLATTENER's table, so each broke the half the
   other kept.
2. **`(p:q:r` with `r = 1` never clears the multiplier.** The note said reproducing it
   "means running abcjs's state machine over the voice at sequence time… a change to WHERE
   tuplets are resolved". It does not. Our model marks **exactly one event** of such a
   group — the same fact `tripletNotesLeft = num_notes` states — so the ratio is already in
   hand at the start arm and carrying it forward is three lines.
3. **`abcts-endings#2`'s last velocity byte.** The note said it needed either a measure COPY

   the copy is `take: 1` and writes no barline, and the measure object still travels

## 🔬 WHAT LANDED, FOR THE SHAPE OF IT

Sixteen, grouped.

**Granularity — a field takes effect WHERE IT IS WRITTEN.** A mid-line `[K:C bass-8]` pushes
its transpose at the clef (`abc_midi_sequencer.js:300-308`), so `CD[K:C bass-8]EF|` sounds
60, 62, 52, 53 and we shifted all four. An inline `[Q:]` is stamped with the voice's
`durationCounter` at the moment it is pushed (`:355-361`), so `CD[Q:1/4=90]EF|` leaves C and
D at the opening tempo; `collectTempoChanges` keyed the change on the MEASURE and doubled
all four.

**Structure the PARSER decides, not the flattener.** A slur mark around a CHORD hangs on the
ELEMENT — one pitch or three, `([C]D)` included — while the flattener reads `note.startSlur`
off the PITCH (`abc_midi_flattener.js:579-582`), so it never reaches `slurCount`. A tie's
`endTie` is stamped on the element FOLLOWING the tied one whatever its pitch, so an open tie
never survives one element: `C-z C|` is two notes there and was one here, while `C-|C|` and
`C-y C|` are untouched — a REST is `el_type: 'note'` and a `y` SPACER is not. And a quarter
tone belongs to the HEAD, so `[^/CE]` is a halfsharp C beside a plain E.

**Substitutions the SEQUENCER makes that the parse tree denies.** `noteElem.duration =
(elem.duration === 0) ? 0.25 : elem.duration` (`:252`) — abcjs's own tree still says 0, so
reading it alone would have denied the rule. And `"".split(" ")` is `[""]`, a ONE-element
array, which is why `%%MIDI drumon` with no pattern gives abcjs a drum track holding its
`program` row and nothing else: we wrote three tracks where the file has four.

**Scope — a voice is not a measure, and a measure is not a whole note.** `tripletMultiplier`
is per VOICE over a flat element stream (`:253-277`), so `(3CD|EFGA|` is a triplet whose
third member is the E of the next bar. A multi-measure rest is as long as the METER says —
`Z3` is `1.5` under `M:2/4` and `3` under `4/4`, asked of abcjs at three meters, and 4/4 is
the one where our whole-note assumption agreed.

**The repeat resolver — five findings, all instrumented.** `addBar` pushes `endRepeat`,
`startEnding`, `startRepeat` in THAT ORDER on one bar element (`synth/repeats.js:16-21`);
the note at the head of our `resolveRepeats` said so and the code had the last two reversed.
`[]` is TRUTHY, so a quoted `["first"]` that parses to no numbers still pushes a section
whose empty `endings` makes the repeat the PLAIN kind. The gap span's guard is
`section.index - 1` and its END is `section.index`. A volta on the FIRST measure is a
section the bar loop structurally cannot see, because it reads each barline's volta off the
measure AFTER it. And a span can stop INSIDE a measure — the `take` truncation above.

**And `%%bagpipes` is `program = 71`**, whose other half is dead code in abcjs: the
flattener's `case "bagpipes": bagpipes = true` assigns a variable read nowhere else in the
file.

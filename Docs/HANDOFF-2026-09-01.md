# Handoff 2026-09-01

## ▶️ START HERE

**A NEW AXIS OPENED AND IT IS THE ONE THE PRODUCT IS JUDGED ON.** Every gate in this repo
renders `src/` under Node against goldens harvested from abcjs **under jsdom**, and
`dump-svg.js` PATCHES `getBBox` with calibrated tables because jsdom has no layout engine.
`golden-widths.ts` reproduces those tables and its own header says reproducing them "makes
our real output diverge from a browser's, which is the point".

So the 691 goldens assert **"abcts matches abcjs GIVEN SYNTHETIC TEXT METRICS"**, and
nothing had ever asked what abcjs draws when it measures for real.

    scripts/zzlive.mjs     abcts and abcjs 6.7.0 in ONE WebKit page, diffed live
    scripts/zzcontrol.mjs  ladders: `size`, `dirs`, `tempo`, `abc` — one per rung
    scripts/zzpair.mjs     one fixture, both engines, element by element

    live gate today: 3 of 685    (231 when the axis opened; 8 before the tempo x)

⚠️ **AND THERE IS NO STORED GOLDEN THAT COULD REPLACE IT.** Measured (`d4b7022`): abcjs
does NOT render byte-identically in WebKit and Blink — 230 of 691 differ between them.
Single glyph advances agree exactly; multi-character widths and bbox heights do not. **So
"byte parity in a browser" has no single target**, and the only coherent oracle is abcjs
running in the SAME browser, live. Re-harvesting the corpus from a browser is ruled out.

WebKit is the default for a reason beyond availability: Studio's editor is CodeMirror 6 in
a **WKWebView**, so for this stack WebKit is the deployment engine rather than a proxy.

## THE ONE RULE THAT PRODUCED ALMOST EVERY FIX

**abcjs MEASURES THE THING IT IS ABOUT TO DRAW; we measured a STAND-IN.** Ten landings, one
shape: a probe string where the real one was wanted, a generic font, the wrong family, the
flat form of a jazz chord, a font's height where a string's was wanted, one line's height
where the whole block's was wanted.

**AND `h + (n-1) * size * 1.2` IS THE STUB'S `getBBox`, NOT A RULE** — four times: the lyric
lane, the jazz chord's nested tspans, the `%%begintext` block, and `dump-svg.js` itself.
Wherever a multi-line height is COMPUTED from one line, abcjs measured the whole string once
(`getTextSize.calc` over the join) and a browser disagrees in the last bits.

**AND THE OWNER'S STEER — THE ORDER OF CALCULATIONS — PAID TWICE.** abcjs divides by
`spacing.STEP` FIRST and multiplies by a lane count SECOND; building a length and dividing
once at the end is `(h*n)/STEP` against `(h/STEP)*n`, the same number for one lane and not
the same float for more. Landed above (`805a9a1`) and below (`fb3fb17`).

## ✅ CLOSED SINCE — THE TEMPO'S SUB-PIXEL X (`35d7031`), 8 → 5

A FRACTIONAL x measures one sub-pixel wider. WebKit, `"left"` bold Times 20px:

    x = 0, 100, 166      27.765625
    x = 0.7, 166.7       27.781250      exactly 1/64

abcjs measures the element it JUST DREW (`getTextSize.calc`'s fourth argument), at the real
x, and the tempo advances `preWidth + preWidth/length`, so on a four-letter word that
quantum lands as 0.02px on the mark's note, its `= 170`, its `post` and everything after.
`visual-selection-02`, `mouse-click-01` and `tablature-15` were all this, on BOTH marks.

**AND "PASSING AN x AT THE EXISTING SITE CHANGES NOTHING" WAS RIGHT ABOUT ONE OF THE TWO
SITES.** The prefix branch already rebuilds a HEADER tempo from the solved x — every other
prefix element is merely PLACED — so passing `cursor` there closed it at once. A MID-TUNE
`[Q:]` is translated like an ordinary music element and its measure-pass cursor is
BLOCK-LOCAL: not an x disagreeing in the last bit, a **different x entirely**. Rebuilding it
in the block loop through the same branch closed the rest. The x goes in ROUNDED the way the
emitter writes it, because `roundNumber(x)` is the attribute the browser lays out from.

⚠️ **AND THE LADDER THAT PROVES IT NEEDED A FRESH DOCUMENT PER RUNG — abcjs'S TEXT CACHE IS
MODULE-GLOBAL AND OUTLIVES A RENDER.** `scripts/zzcontrol.mjs tempo` first reported NINE of
thirteen rungs differing on a build whose every rung is byte-identical **measured alone**.
`var sizeCache = {}` sits at `write/svg.js`'s MODULE scope and its key is
`text + JSON.stringify(attr)` — the font attrs, with **no x** (`:306`, `:316`;
`get-text-size.js`'s `hash.attr` confirms the shape) — so the first width abcjs measures for
a string under 20 characters is the width **every later render in that page gets**, at
whatever x it is drawn next. Sharing one document made rung k depend on rungs 1..k-1, which
is the one property a ladder exists to remove. `zzcontrol` resets the document per rung now;
`SHARE=1` keeps the old behaviour. And the ladder was checked the way this repo checks a
probe: **11 of 13 rungs differ with the fix stashed, 0 of 13 with it.**

**AND THAT CACHE IS A DIVERGENCE OF OURS, MEASURED AND DELIBERATELY NOT LANDED.** Ours
caches per measurer and now keys on the x; abcjs caches globally and does not. So a HOST
page rendering the same short string at two different x's — Studio's WKWebView is exactly
that — gets abcjs's FIRST width and our TRUE one. **No gate here can see it**: every gate
renders fresh, and `zzlive` reads 5 of 685 either way. Reproduce with
`SHARE=1 node scripts/zzcontrol.mjs tempo`, which goes to 9 of 13. The fix is a
module-scoped cache keyed without x — small and understood, and a behaviour change that
makes our output depend on render HISTORY, so it is **the owner's call** rather than a
tidy-up.

## ✅ CLOSED SINCE — EVERY `%%<type>font` LANE (`5092802`), 5 → 4

**TEN SITES, ONE DEFECT, AND IT IS THIS ARC'S OWN RULE.** Each asked
`textHeight`/`textWidth` for a DEFAULT PROBE IN A DEFAULT SERIF where abcjs hands
`getTextSize.calc` the directive's whole font object — so the lane, the advance or the rect
came out the same height whatever the `%%…font` named. The part label, `wordsfont`,
`historyfont`, `measurefont`, a mid-tune `T:`, `tempofont`'s two advances, `repeatfont`'s
`minspacing`, and `$N` rows in the bottom block. `visual-options-01-fonts` is byte-identical
in WebKit and `misc-06-title-1bold`'s page height is exact.

**AND THE PROBE STRING IS ABCJS'S, WHICH IS NOT THE SAME AS NOT HAVING ONE.** `addTextIf`
measures `"A"`, `richText`'s empty arm `"i"`, `addMultiLine` `"A"` — never the row's own
text, and its comment says why. `Subtitle` is the exception and measures `info.text`. Ours
used `'Mg'`, which carries a descender the probes do not, so the SIGN of the error moved
with the face.

⚠️ **AND LEAVE-ONE-OUT IS WHAT MADE AN EIGHTEEN-DIRECTIVE FIXTURE TRACTABLE.** Deleting one
LINE of the fixture at a time and printing the page delta named each contributor
separately — `%%partsfont` 1.81px, `%%wordsfont` 0.97, `%%subtitlefont` 0.22, `%%measurefont`
0.06, summing to the observed 3.06 exactly — and a control ladder per contributor then
proved each fix. It is the complement of the build-up ladder: a ladder isolates a CAUSE,
leave-one-out ENUMERATES them.

## ✅ CLOSED SINCE — CSSOM SERIALISATION (`0e7abc4`), 4 → 3

**AND IT WAS FILED AS THE OWNER'S CALL BECAUSE THE QUESTION WAS PUT ABOUT THE WRONG THING.**
"Matching one browser's serialisation breaks the other by construction" is TRUE of a string
we EMIT and FALSE of declarations we SET. `setScale` assigns eight properties on the root
`<svg>`'s style (`write/svg.js:71-83`) and the attribute is whatever that browser's CSSOM
serialises — WebKit collapses `-webkit-transform` onto `transform`, writes `scale(0.8, 0.8)`
with a space and `0px 0px`, drops the six it does not know; Chrome KEEPS
`-webkit-transform-origin-x/y`; jsdom, which harvested the goldens, serialises three. So the
emitter's attribute cannot be right in ANY browser and no other string is right in both.

Re-running abcjs's eight assignments over the INSERTED element hands the job to the browser:
`abcts-ledger-gaps-tune5` is byte-identical in **WebKit and in Chrome**, which is the check
that matters — one alone would have proved nothing. Contained to the compat layer's DOM
path, so the emitted string and the 691 goldens are untouched.

⚠️ **THE LESSON IS ABOUT THE FILING, NOT THE FIX.** The note called the answer
"architectural — we emit SVG text, abcjs builds nodes", and the whole change is one function
over ONE element. **"Architectural" is a claim about scope and it can be measured too.**

## WHAT IS LEFT — 3, and two of them are not defects of the renderer

**1 · TWO FIXTURES THAT ARE BYTE-IDENTICAL RENDERED ALONE.**
`visual-selection-01` and `svg-per-line-01` pass `zzpair` exactly and fail `zzlive`, and the
whole of the difference is the cache below. Nothing in the layout is wrong.

**2 · `misc-06-title-1bold` — ONE ULP, AND IT IS THE VISIBLE EDGE OF A 0.765625 THAT
CANCELS.** The page height is exact; one bottom-block row's y reads `460.779` against
abcjs's `460.77900000000005`, and every row after it agrees because the next add absorbs it.

**INSTRUMENTED, and the answer is not where the symptom is.** The bottom block's emitted y
is `t.y + oy` — a block-local walk plus a base, which is the `local + base` hazard
`bottomTextBlock`'s own doc block warns about and takes `from` to avoid; taking `from` fixed
the walk WITHIN the block and the `+ oy` at the emitter puts the grouping back. The TOP
block solved exactly this by being built at the page's cursor and carrying `pageY`
(`svg.ts:1711` writes that RAW, bypassing `oy`).

⚠️ **BUT THE PAGE WALK DISAGREES WITH THE EMITTER'S FRAME BY 0.765625 — A REAL NUMBER, NOT
A ULP.** Measured with a probe on `pageEnd`'s own walk:

    emitter    bottomStart 425.544625 + oy 35.234375  =  460.779
    pageEnd    walked to that row                     =  461.54462500000005
                                                         ^^ abcjs's tail, 0.765625 high

So the walked cursor already carries abcjs's last bits and the two frames are 0.765625
apart, while the PAGE HEIGHT off that same walk is exact — **two errors cancelling, the
eighth time on this branch.** Stamping `pageY` from the walk is the right shape and would
land a 0.77px error today: the plumbing was written, measured, and reverted.

**So the work is the 0.765625, not the ULP.** `bottom = last.originY + systemHeight(last)`
and `pageEnd`'s per-system walk are two derivations of the same cursor; find where they
part. Dead ends, both measured: a per-phrase `richHeight` (abcjs's actual rule — ported,
moved NOTHING, reverted rather than kept unmeasured), left-associating
`(originY + leading) + heightPitch * STEP` (moved nothing), and every `%%setfont` control
rung, all byte-identical.

**3 · A HELD SYLLABLE TAKES THE DEFAULT FONT — measured, fixed, REVERTED (`85356b9`).**
`%%vocalfont Times-Roman 20` over `C4 D4` / `w:laa_ la` draws the held `&nbsp;` at 17 BOLD
where abcjs draws 27 normal. Inheriting the directive closes the control EXACTLY and takes
four gates red, one named *"does NOT realize %%vocalfont — abcjs parses it and never draws
it"*. Scope to the held/empty syllable ALONE and prove against THOSE gates, not the control.

### ⚠️ AND THE CACHE DIVERGENCE IS NOW MEASURED BOTH WAYS — DO NOT RE-TRY THE NAIVE PORT

abcjs's `var sizeCache = {}` is at `write/svg.js`'s MODULE scope and its key is
`text + JSON.stringify(attr)` — the font attrs plus the CLASS, with **no x** (`:306`,
`:316`). So the first width it measures for a string under 20 characters is the width every
later render in that page gets. Ours caches per measurer and keys ON the x, which is what
the tempo fix needs.

**Porting it — module-scoped, x dropped from the key — takes the live gate from 4 to SEVEN**,
because it re-breaks all three tempo fixtures: each engine's cache freezes at ITS OWN first
x, and the two only track once every x already agrees. The two are coupled and the naive
port is strictly worse. A faithful one would have to key on the CLASS as abcjs does, which
`TextFont` cannot express today. Measured, reverted, written down.

## WHERE TO START

### 1. PORT `calcWidth` — the largest item by pixels, and it was wrongly written off

**`tests/corpus-abcjs-ranked.txt`'s top two are both this**, and the checkpoint has the
mechanism verbatim: five ASCII per-character tables in
`../abcMusicKit/Tools/abcjs-debug/dump-elements-char-widths.js`, chosen by SIZE with three
of the six brackets resolving to `repeatfont` because their key does not exist, and
`widths[ch] || 8` for everything outside them. `dump-svg.js:62-84`.

Ours is `textWidth` in `layout.ts`, a per-em estimate with a `FULL_WIDTH_ADVANCE = 1.0`
branch for CJK — which is the OPPOSITE of the golden's 8. Replacing the body with
`calcWidth` is mechanical; the only design question is the mode split, since `textWidth`
takes no `strict` today and has 16 call sites. `abcjs-strict` must reproduce the fallback
(v1 does); `abcjs-extended` are where the correct widths belong.

Expected: `little swallow` dx 24.19, `visual-tablature-17` dx 499.4, and every title width
in the corpus — a 27px title is currently measured at 27px and the golden measures it with
the **17px** `repeatfont` table.

Do `%%jazzchords`' nested-tspan height (`dump-svg.js:120-124`, 38.4px on
`visual-misc-03`) in the same pass — same file, same decision.

### 2. THE SYSTEMIC 0.03px

Every fixture carries a rigid `oy` of about **0.03px**, and a sharp key signature adds
another **0.04** — measured on `K:C` / `K:A` control pairs with nothing else in them, so it
is not a feature interaction. A dozen fixtures at the foot of the ranked table read
0.06–0.07 and are otherwise exact; closing this moves the `0.05` count by more than any
remaining feature would.

Start from `K:C` / `cd|` and nothing else, and compare the STAFF LINE. Our top line and
abcjs's differ by 0.03 there, so it is placement, not a glyph. Suspect the clef's declared
box (`symbolHeightInPitches + clefPos + ofs`) against our `2 * glyph.height` — the same
0.0235-of-a-space class of difference that once put eight fixtures 0.184px high.

## STILL NEEDING A DECISION, NOT A COMMIT

**The gate hides failures.** All eight per-fixture assertions live in one `it`, so the first
to fail ends it. Collecting all four axes before asserting is the honest fix and will show
more red before it shows less.

**A grace note before a `y` spacer is dropped.** `Rest` has no `graceNotes` field and the
model says so deliberately. abcjs disagrees for a SPACER. `visual-tablature-10` is
`(f3 {a})y` at `oy` −9.6.

**`frere-jacques`'s `M:` arrives after prose.** Its `M:4/4` sits on line 14, after the `+:`
lines that strict mode scans as MUSIC, so `score.meter` is NULL and measure 1 carries a 4/4
change. abcjs prints it on the system where the prose ends; we have no line for that prose,
so the mid-tune meter draw is suppressed when there is no meter in force. The honest fix is
a line for the prose.

**The overlay pad's second rule.** For lines BEFORE the one carrying the `&`, abcjs mirrors
the main voice NOTE FOR NOTE rather than one rest per measure (`tune-builder.js:539-563`).
The two agree when a measure holds one note, which is every case in the corpus so far.

**The leading-header split** — `parse-book_parser-04-wed` is the one remaining TUNE COUNT
mismatch, 2 against 1.

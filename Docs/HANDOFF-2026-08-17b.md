## WHAT TO DO NEXT, IN ORDER

### 1. The API surface — 17 absent, and it is all BEHAVIOUR now

`Editor` / `EditArea` / `TimingCallbacks` / the three animation functions / `tuneMetrics` /
`setGlyph`; the seven `synth.*`; and `tune.makeVoicesArray` / `tune.addElementToEvents`.

**`TimingCallbacks` IS THE ONE THE WORK JUST UNBLOCKED.** It consumes `noteTimings`, which
now carries its geometry — `line`, `top`, `height`, `left`, `width`, the two char arrays —
so a cursor has everything but the DOM nodes. Its own contract is a timer, a `beatCallback`
and an `eventCallback`, which is host playback in the same sense `CreateSynth` is; read
`src/compat/synth.ts`'s note before deciding how much of it is ours.

**`makeVoicesArray` and `addElementToEvents` are the same object in two shapes.** Both hand
back abcjs's LAYOUT elements (`{top, height, line, measureNumber, elem}` where `elem` is an
`AbsoluteElement`), so exposing them means projecting that object rather than the answer it
produces — the trade `topText` made. The GEOMETRY they carry is built already
(`geometryOf` in `src/compat/index.ts`); what is missing is the element shape.

### 2. `deline`'s twelve rows — five mechanisms, all measured

`CHECKPOINT-2026-08-17b.md` §2.1 names each. Two want a PARSER field that does not exist:
a per-line `style` (`multilineVars.style`, which `createVoice` reads once a `style=` has been
seen) and a per-line FONT (`setLineFont`'s "only if it changed"). One wants the ENGRAVER's
own mutations — `%%maxStaves` leaves an undrawn line's `staff.clef` without an `abselem`,
which is what makes `deline` unshift a clef there. One is prose spans in `frere-jacques`.

### 3. `setupEvents`'s 324 rows — three mechanisms, all written down

**AND THE BIGGEST IS ONE NUMBER: THE SYSTEM'S OWN RIGHT EDGE, abcjs's `staffGroup.w`.**
Every row whose successor is on the same system has an exact `endX`, because that value is
the next row's `left`; a row at the END of a system runs out to `staffGroup.w` instead, and
297 rows do. Measured, and neither offset is it in both cases:

    stretched line   abcjs 755      our `LayoutSystem.width` 740, ink right edge 725
    short line       abcjs 201.111  our width 216.111, ink right edge 194.111 (bar w = 1)

abcjs's is the cursor ITS layout ended at — the target plus the left margin when the line
was justified, and the natural end when it was not. Ours is `max(musicWidth, proseWidth)`.
**DO NOT PICK AN OFFSET**: the layout should record the x it laid each line out to, beside
`width`, and the stretch decision that distinguishes the two cases is already in
`justify`'s `isLast` branch. ⚠️ And measure it at the COMPAT's width: `systemWidth` is the
PAGE in layout units, `(staffwidth + 2 × padding) / UNIT_PX`, so a probe passing 740 lays
out a different tune from the one the gate renders at 770.

The other two: the overlay one is a MODEL question (our padding is per tune, abcjs's
back-fill is per line before the `&`); the height one is a REPORTED extent, with both
engines placing the systems identically.

### 3b. `TimingCallbacks` needs that number too

`doBeatCallback`'s `position.left` interpolates between `ev.left` and `ev.endX`
(`abc_timing_callbacks.js:216-228`), so the cursor's x is only as good as `endX`. Its
`lineEndCallback` reads `timing.top`, which IS built. The class itself is 436 lines and
deterministic once `requestAnimationFrame`, `setTimeout` and `performance.now` are stubbed:
**a harvest can drive `doTiming(t)` at 16ms steps and record every callback**, which is the
oracle to build before a line of it.

### 4. `tuneMetrics` is NOT the small one it looks

`getMeasureWidths` lays the tune out at width **0** (`engraver-controller.js:139`) and reads
voice 0's bar positions. abcjs's width-0 layout COMPRESSES to the rods — `twinkle`'s first
measure is 70.035 wide where ours is 4 × 42.426 — and our layout has no such mode: at
`systemWidth` 0, 1 and 670 it produces the same natural spacing. Building it means a
compress-to-minimum path in the packer, not a walk over what we have.

### 5. The one measured-and-written-down left

A chord's ties are per pitch (`tests/chord-tie.test.ts`, two `it.fails`). The other two —
the `&` overlay's late `end` and `%%maxStaves`'s truncated clock — are CLOSED.

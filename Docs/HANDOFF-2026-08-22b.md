operations, and a clef that lands the line on a `.xx5` boundary rounds the other way. Only

**The STEM half of this pair is already fixed** — see §4.5.

**b. `V:… scale=` AND `cue=` — THE FEATURE.** Both are `voiceScale`, which abcjs DOES save

scale for GRACE notes only and no per-voice one; threading it is a session's work, not a
patch. Measured: `scale=1.5` draws the untouched baseline, 21328 bytes against our 20315.

**c. TWO WARNINGS THIS ENGINE DOES NOT EMIT.** Both geometry-exact and diagnostic-only:

### 1. THE DECORATION TABLES — 96 NAMES, 93 COMPARABLE, THREE WRONG

- **`!slide!`'s EXTENT.** Its curve was already byte-exact and its reserve was missing, so

  drawing recomputes `isTie` and reaches `calcTieDirection`, which says above.
- **`~(` / `~)` ARE `glissando(` / `glissando)`** — case labels sharing an arm in the
  WRITER's switch (`decoration.js:341-348`), never spelled upstream.
- **A GLISSANDO INSETS BY HALF THE ELEMENT, NOT HALF THE NOTEHEAD** — `anchor1.w` off the
  ABSOLUTE element, which an unbeamed up-stem flag grows past the head (15.902 against
  9.81). `NoteAnchor.absWidth` carries abcjs's `max(dx + w)` over the `addRight` children
  only: heads, unbeamed flag, dots.

⚠️ **`!glissando)!` AND `!~)!` WITH NOTHING OPEN CRASH abcjs**, so no golden can exist for
either. Ours renders both; a crash is not parity.

### 2. `checkLastBarX` — FOUND BY A CONTROL, NOT BY A VARIABLE

### 4. `%%MIDI` — TWO, AND THE FIRST ENUMERATION AIMED OFF THE SVG

All 53 sub-commands, one tune each. **NOT ONE OF THEM MOVES THE DRAWING** — the byte gate
is 0 of 56 on the fixture and `synth.sequence` 0 of 191 — so `tune.formatting.midi` is what
states the defects, which is exactly why the list was worth taking off the SVG gate.
`midiCmdParam1String` pushes the RAW TOKEN (`ptstress 1` is `["1"]`, not `[1]`) and
`midiCmdParamFraction` pushes TWO INTEGERS (`grace 1/4` is `[1, 4]`, not `["1/4"]`).

⚠️ **AND `%%MIDI` TOKENISES WITH `alphaUntilWhiteSpace`, WHICH IS WHY `1/4` SPLITS AND

### 5. `V:… style=`, AND THE LEAK THAT KEEPS IT UNFINISHED

The arm that reads `V:`'s modifiers had CLAIMED to read `style=` since it was written and
did not. All five shapes are byte-exact on ONE voice. ⚠️ **AND IN abcjs IT LEAKS INTO EVERY
VOICE ENGRAVED AFTER IT** — `pushCrossLineElems` saves the slurs, ties, endings, COLOUR and
SCALE per voice and NOT the style (`abstract-engraver.js:92-107`). Measured both ways:
`V:1 style=x` gives the lower staff x heads it never asked for, and `[V:2 style=x]` reaches
voice 1's SECOND line. Not reproduced — the leak is a running value in (line, staff, voice)
ENGRAVING order where this parser resolves per voice at parse time, and source order is
engraving order only for interleaved `[V:…]` lines.

### 6. THE K: MODIFIERS — FIVE, AND THE SWITCH IS NOT V:'s

- **`C`, `F` AND `G` NAME CLEFS, IN EITHER CASE** — ⚠️ only after `clef=`; a bare `K:C G`
  is an unknown parameter, and reading a bare letter would make the KEY's own letter a clef.
- **A MODIFIER'S OWN `=` IS ONE OF THE THREE ACCIDENTAL SIGNS.** `K:C clef=C` read a
  natural on C and widened the staff by 15.4px. ⚠️ **AND THE FIX IS A STOP, NOT A SKIP** —
  accidentals are a PREFIX: `K:C =f clef=alto` draws the natural, `K:C clef=alto =f` draws
  nothing. ⚠️ **AND NOT EVERY `x=y` IS A MODIFIER** — `K:C=c` really is a natural.
- **`m` IS MINOR WHENEVER THE NEXT CHARACTER IS ` `, `^`, `_` OR `=`** — `getMode`'s own
  truncation, with abcjs's comment "this will handle the case of 'm'". So `K:C m=B` is C
  MINOR WITH A NATURAL B, and `getMode` consumes only the alphabetic run so the `=B` still
  scans. With the mode slot filled (`K:Cmaj m=d`) the token IS the middle override.
- **`middle=` REACHES THE CLEF FALLBACK**, exactly as `stafflines=` does.
- **AN UP STEM'S ANCHOR IS THE CENTRE PLUS A HALF, NOT `(centre - half) + w`** — abcjs
  hands `printStem` ONE number. `153.91499999999999204` against `153.91500000000002046`.

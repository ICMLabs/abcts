## 2. THE ORACLE, AND THE TWO THINGS IT SAID FIRST

`tests/corpus-selection/golden.json` is abcjs's four `doSelectionTest` cases —
**389 selectables** — extracted from `tests/visual/selection.test.js` by EVALUATING it with
`describe`/`it`/the helper replaced, and then **generated by RUNNING abcjs 6.7.0**
(`scripts/harvest-abcjs-selection.mjs`). What the test file itself claims is kept beside
each row in `testFileSays`, and it disagrees with abcjs on **eleven rows**:

### 2.1 A written `C` under `clef=tenor` and `clef=bass` sounds 60 in 6.7.0

The file expects 48 and 72. The four OCTAVE-MARKED clefs — `treble±8`, `bass±8` — agree
with it exactly, so what the file asserts is a clef-octave transposition that 6.7.0 applies
only to the `±8` forms. **THE ORACLE IS WHAT abcjs DOES**, so the corpus records 60 and the
file's claim beside it. Second time this distinction has earned itself, after
`output-miss-accidental` in the transpose arc.

### 2.2 Nine `y` attributes, and that one is OUR HARNESS — located to the digit

Nine text rows of `selection-multiple` sit 1, 2, 4 and then 55-60px above the file's
numbers, accumulating down the page. The cause is not abcjs:

**`%%titlefont Times New Roman 22.0` renders at 29px, and `dump-svg.js`'s `fontHeights` —
the calibrated WebKit table every golden in both corpora is generated with — has SEVEN
entries, none of them 29.** It falls through to `size + 2` = 31 where a browser measures
32.13.

MEASURED, not reasoned: putting 32.13 into the table reproduces the test file's 82.34 for
the subtitle to the digit, and changing the 22px entry (the obvious suspect, since the
directive says 22) moves nothing at all. The ratio is the table's own — 27→29.91 and
21→23.27 are both 1.108 — and 29 × 1.108 is 32.13.

**This is a harness-level tolerance nobody had written down**, and it reaches further than
this gate: `grep -ho 'font-size="[0-9.]*"'` over both golden trees finds **46 text elements
at a size outside {15,16,17,19,20,21,27}**, every one of which abcjs-in-a-browser would draw
at a different height. `GOLDEN_TEXT_HEIGHTS` reproduces the fallback ON PURPOSE — byte
parity with the goldens is what `abcjs-strict` means — so nothing here changes, and the
oracle keeps the harness's number. But the goldens and a browser part company there, and
`dump-svg.js` lives in `../abcMusicKit`, which another lane owns.

### 2.3 What is NOT gated, and it is stated rather than fudged

`size` is `svgEl.getBBox()` **on a GROUP** — the browser's ink measurement of glyph
outlines. jsdom implements it for nothing at all and `dump-svg.js` stubs it for
`<text>`/`<tspan>` only, so no oracle for it can be produced in this harness. The test
file's numbers are carried in the corpus and **nothing compares them.**

## 3. WHAT LANDED

### 3.1 The join is a REFERENCE, not a position

abcjs's selectable array holds `absEl.abcelem` — the very `tune.lines` element — so its two
public surfaces agree by IDENTITY. Ours are separate objects and something has to join
them. Pairing them POSITIONALLY (the k-th drawn note against the k-th event of the k-th
voice) breaks the moment `%%score` reorders the staves or an `&` overlay becomes a voice of
its own, **both of which this engine already does**.

So `LayoutElement` carries `sourceEvent` and `sourceClef` — a reference, read by NOTHING in
layout or in the emitter — and `projectionOf` hands back the map from event to projected
element. `tune.lines` and the selectables are then the same objects here too, which is what
lets the engrave-time and flattener fields be stamped onto one and read through the other.

**And half the gate was proven before it existed**: `data-index` is byte-exact on all 356
sibling rows and all 188 in-repo ones, so the ORDER and the COUNT follow a walk that is
already right. What this gate measures is the `abcelem`.

### 3.2 The rules ported, each from a named abcjs function

- **`startBeam`/`endBeam` ARE A STATE MACHINE OVER THE STREAM, NOT THE DRAWN BEAM**
  (`tune-builder.js:174-220`, `:880-945`). Two pointers — the note a beam could start on
  and the one it could end on — flagged whenever the run closes. Three of its four rules
  say what does NOT break a run: **a REST changes nothing at all**, so `C/D/ z C/D/` keeps
  ONE potential run across the silence though two beams are drawn; a run of ONE is never
  flagged; and the SPACE that ends a run is the SOURCE's, not the layout's. 38 rows, and
  reading our own beam groups would have differed on every one of those cases.
  - The space is read at `endChar - 1`, not at `endChar`: the element's span has **already
    eaten its trailing whitespace**, which is the asymmetry the tiling rests on.
- **A SLUR IS A NUMBERED PAIR AND THE NUMBER IS `chordPos * 100 + 1`**
  (`tune-builder.js:697-721`) — **101** for an ordinary note, because a slur written before
  one is moved onto `pitches[0]` and numbered as that head. Grace notes take chord position
  20. The stack is per VOICE and spans the tune, so it is threaded through the lines rather
  than being local to one.
- **abcjs's PARSER FOLDS THE DECORATION SPELLINGS** — `<(` is `crescendo(`, `>` and
  `emphasis` are both `accent`, `^` is `umarcato` (`abc_parse_settings.js:95-110`). The
  same table bit the geometry from the other side in August: `!>!` drew the sforzato and
  then failed `closeDecoration`'s `name === 'accent'` test, and every accent in the corpus
  sat one pitch out.
- **A GRACE'S DURATION IS RELATIVE TO A SIXTEENTH, NOT TO `L:`** —
  `note.duration / (default_length * 8)` (`abc_parse_music.js:694`), so a bare grace is
  0.125 whatever the unit note length is.
- **A TUPLET'S MARKS RIDE ON THE FIRST NOTE AND THE LAST** and nothing between — the same
  asymmetry the chord grid found from the other side, where abcjs's beat count is wrong for
  every tuplet BECAUSE the ratio is stamped once. `tripletMultiplier` needs no new model
  field: sounding over notated IS the ratio, exactly.
- **A TIE IS A PROPERTY OF THE PITCH** (`abc_parse_music.js:427`) and its closing head is
  marked too — `endTie` on the pitch of the next element carrying the same note.
- **AN EXPLICIT ACCIDENTAL IS NAMED ON THE PITCH**, and only an explicit one.
- **A REST IS SELECTABLE AND NOT DRAGGABLE.** `canSelect` reads the ABCELEM's `el_type`,
  which is `note` for a rest; `isSelectable` reads the ABSELEM's `type`, which is `rest`.
  **Two type fields one line apart in `draw/absolute.js`, and only one of them says rest.**
- **`verticalPos` IS `pitch - mid`** (`tune-builder.js:918`) and abcjs counts from the
  first ledger BELOW the staff where our steps count from the middle line — exactly 6
  apart, checked on all three clefs of `selection-clefs` rather than assumed.

### 3.3 The flattener writes back onto the element

`currentTrackMilliseconds`, `currentTrackWholeNotes` and `midiPitches` land on the very
`tune.lines` element (`abc_midi_flattener.js:526-596`). **Two rules, and they are not the
same rule**: the TIMES accumulate — a number becomes an array the moment a repeat brings a
second, different value, and a duplicate from another voice is dropped — while
`midiPitches` is EMPTIED on every visit, so an element reached twice keeps only the last
pass.

And `midiPitches` holds **the same objects that go into the track** (one `p`, pushed to
both), which is why the `gap` an element takes AFTER the push is visible there. Their
`startChar`/`endChar` are the ELEMENT's, so the stamping is in `compat`: only that side
holds the projected span.

### 3.4 A standalone `K:` or `M:` line is not in the stream

It restamps the STAFF; only the inline `[K:…]` / `[M:…]` form joins the voice's stream.
Ours emitted both, and **because the spans TILE, the extra element swallowed the newline and
opened the next line's first note one character early** — six of `selection-clefs`'s seven
rows, and 549 characters of the lines gate. The engraver already knew the rule from the
other side: a body `K:` is drawn as a whole staff's key, which is what lets `%%keywarn`
remove a cautionary one without touching the line's own signature.

That one landing took `selection-clefs` to byte-for-byte and `tune.lines` from 250,226 to
250,775 characters.

- **`selection-multiple` 0 of 221 and `selection-tempo` 0 of 8** — both are `selectTypes:
  true`, where every drawn thing is selectable, and we emit only the notes and rests. The
  missing entries are the other TEN `Selectables.add` sites: the non-music text rows, the
  voice name, the brace, the endings, the triplets, the curves, the dynamics — plus the
  staff-extra clef / key / meter and the `bar`, `tempo` and `part` elements, whose abcelems
  the projection does not carry at all. Their shapes are small and named in the corpus
  (`clef` is `{type, verticalPos, clefPos}`, `timeSignature` is `{type, value}`, an ending
  and a triplet are `{el_type, startChar: -1, endChar: -1}`).
- **`selection-none` 141 of 153**, and its twelve open rows are TWO defects that
  `tests/lines.test.ts` already names — measured from a second surface now:
  1. an element's span stopping short of a trailing `-` or `)`;
  2. the six element types the projection does not carry (`tempo`, `clef`, `midi`, `style`,
     `color`, `part`), whose characters are swallowed by the note before them.
  Plus **one beam pair** whose run our machine closes a note early.

### 4b. AND THE ELEMENT SITES LANDED AFTER THAT — the join is THREE joins

A note or a rest joins by its model event; a BARLINE by where it was written, the RAW range
because the tiled `startChar` moves; and the CLEF, KEY and METER by neither, since abcjs
hangs those on the STAFF rather than in the voice's stream. **The staff's furniture carries
no `startChar` at all** — not `-1`, ABSENT — which was the entire difference on the two rows
that closed. `clefPos` and `verticalPos` are derived, not tabled: the clef's line doubled,
and this staff's middle line measured from a treble staff's.

A KEY SIGNATURE is measured and deliberately NOT built — its `accidentals` are
`{acc, note, verticalPos}` where `note` is the name AT THE POSITION DRAWN, so B♭ major
gives `B` and `e`, upper and lower case in one list, moving with the clef.

## 7. THE RULES THIS SESSION PAID FOR

- **A DISAGREEMENT WITH THE ORACLE IS EVIDENCE ABOUT THE HARNESS TOO.** Nine of the eleven
  rows where abcjs's own suite disagrees with abcjs turned out to be our text metrics, and
  the way to tell was to VARY the suspected input and watch: the obvious suspect (the 22px
  directive) moved nothing, the real one reproduced the file's number to the digit.
- **TWO TYPE FIELDS, ONE LINE APART.** `canSelect` and `isSelectable` read different
  `type`s of the same element and only one says `rest`. The same shape as
  `openingBarlineChord` / `closingBarlineChord` last session.
- **A RATCHET THAT NAMES ROWS CATCHES WHAT A COUNT CANNOT** — the re-ratchet script split
  the ranked report on whitespace and turned `sib/little swallow-tune0` into `sib/little`,
  putting a FAILING tune on the passing list under a name nothing matches. The next run
  went red on it.
- **A SUM CANNOT SEE AN ORDER; A COUNT CANNOT SEE A CASE.** `selection-none` at 141 of 153
  and `selection-multiple` at 0 of 221 are the same implementation — one case simply asks
  for ten draw sites the other never reaches.

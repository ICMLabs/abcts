## WHAT TO DO NEXT, IN ORDER

### 1. THE OVERLAY MODEL — 21 + 14 rows, and TWO WRONG ANSWERS ALREADY MEASURED

Every open `setupEvents` row and the one open `makeVoicesArray` tune are this. Ours pads
every measure of a voice with ONE invisible rest of the measure's duration (`padOverlays`),
so a row reads `startCharArray [82,82,82]` where abcjs reads `[82,85]`.

**`tune.lines` ALREADY REPRODUCES abcjs EXACTLY** — `npx tsx scripts/zzovl.ts` against
`/tmp/gp/ovl.js` prints the same five lines of 3, 3, 3, 2, 2 voices for
`synth-flattener-21`, element for element. So the algorithm is ported; it is the MODEL that
is padded differently, and the fix is to SHARE that resolution rather than re-derive it.

⚠️ **Two re-derivations were tried and both are measurably wrong. Do not repeat them.**

1. **Per-line layering in `timing.ts` alone** — the layer voices lose the GEOMETRY join.
   The rows' `left`/`width` come from `geometryOf`, which is keyed by MODEL EVENT IDENTITY;
   synthetic copies are in no layout, so `synth-flattener-22`'s row 0 reported `left 49.051`
   for abcjs's `70.846` and the gate went from 3,345 to 3,309.
2. **The same rule inside `padOverlays`** (so all three consumers see it) — 3,324 rows, ONE
   byte fixture red (`flattener-21`'s clef moved 5px) and ONE audio case red
   (`flatten-rep-and-over`, a note at 8 where abcjs says 10). The audio one is the tell: it
   proves the rule "a line past the last `&` gets nothing" is WRONG. abcjs's pass walks
   EVERY line, so a line with no `&` is back-filled whenever ANY LATER line has one — not
   only before the first — and the guard `staff.voices.length >= s.voices.length` (current
   line's count against the earlier line's) decides how often.

So the shape to build is: resolve the overlays ONCE, in the model, by the same iterative
`while (resolveOverlays(…))` the projection already runs — including the guard — and let the
renderer, `flatten` and `timing` all read it. The three of them expand `measure.overlays`
identically today (`layout.ts:10751`, `timing.ts:430`, `flatten.ts:1103`), which is where
the shared answer has to land.

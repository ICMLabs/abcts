Every rule from the previous handoff earned its place again:

first, and then rendered in WebKit under seven option combinations before a line was
written. **Three of the four rules that matter are not visible in the source:**

| the source says | the browser says |
|---|---|
| `divStyles = "overflow: hidden;" + "height:" + h + "px;"` | it reaches the attribute UNSERIALISED — `overflow: hidden;height:55.40625px;`, a space after the first colon and none after the second. Setting the two properties normalises it: **86 of 87** |
| `parent.style.width = div.style.width` | a NO-OP above scale 1, because `setPaperSize` writes a width only below it — so a horizontal viewport's outer div carries `overflow: hidden` and nothing else |

## 🔬 WHAT LANDED

All three build a wrapper the emitted string cannot carry, so all three sit DOM-side beside
`sizeContainer`, and none exists headless — abcjs's own behaviour, not a shortcut.

- **`oneSvgPerLine`** (`engraver-controller.js:317-368`) — one `<svg>` per top-level `<g>`,
  each in its own `overflow: hidden` div, with a `viewBox` scrolled to where the section was
  drawn and `Sheet Music for "<title>" section N` as both `aria-label` and `<title>`. **A
  section's height includes the GAP ABOVE IT** (`box.y - nextTop`), so the divs tile with no
  seams and `nextTop` advances to `box.y + box.height`. **And the `<title>` is an HTML
  element inside an SVG** — `createElementNS` for the `<svg>`, plain `createElement` for the
  title.
- **`viewportHorizontal` / `viewportVertical`** (`abc_tunebook_svg.js:29-47`) — the host's
  div becomes the viewport and the music moves into a `div.abcjs-inner`
  (`.abcjs-inner.scroll-amount` for the vertical arm). abcjs hands the ENGRAVER that inner
  div, so **everything `setPaperSize` writes lands on the inner one**. They are an
  `if`/`else if` and not a pair of flags: horizontal wins when both are passed.
- **The resize handler, bug and all.** `resizeOuter` declares `width` OUTSIDE its loop and
  subtracts each div's offset from what the last one left, so a second viewport on a page is
  narrower than the first; a div with no `id` is keyed under `"undefined"`. **No gate here
  can see a resize handler, so the only defensible rule is to be abcjs** — reproduced, with
  the reasoning at the site.
- **The Firefox `viewBox` `+1`** is ported. ⚠️ **Its two siblings are not**: `renderer.firefox`
  also has arms in `print-stem.js` and `print-line.js` that abcts has never had. Pre-existing,
  now written down.

## 🔬 THE FINDING THAT IS NOT ABOUT THIS WORK

⚠️ **abcts ATTACHES NO DOM EVENT LISTENERS AT ALL.** Grepping for `addEventListener` across
`compat/` after this landed returns **only the resize handler this change added**.
`setupSelection` (`write/interactive/selection.js`, ~250 lines) is entirely unported: click,
drag-to-change-pitch, `selectionColor`/`dragColor` repainting, the `abcjs-dragging-in-progress`
class, and the `clickListener` a host passes. `tune.engraver.svgs` — abcjs's array of the
split SVGs, which `setupSelection` binds to — is absent too.

**The `selectables` ARRAY is right** (`zzselect` is 0 of 685) and so is every attribute the
markup carries. What is missing is everything that happens AFTER a user touches it, and no
gate in this repo renders a click. That is the honest answer to *"what else does a host
switch on that no gate renders"*: not another option, an **interaction**.

### 1. `S8-layout-tune11` — a STANDALONE `M:` ON A `\`-CONTINUED LINE DRAWS WHERE IT STANDS

Its `dy` is CLOSED (finding 131, 8.37 → 0.01). What is left is `dx` 20.12 on system 0, and
it is ONE missing element, located exactly:

```
abcjs system 0   … bar x=196.51,  timeSignature x=207.51 w=10.93,  note x=244.89 …
ours             … bar x=201.18,  (nothing),                       note …
```

The source is `"Em"ABc def |\` then `M: 9/8` on the next source line. The `\` continues the
printed system, so `startNewLine` never fires — and abcjs draws the meter INLINE, mid-system,
right after the barline. That is a THIRD case, distinct from both halves of finding 130:

```
standalone `M:` on its own line      -> the NEXT line's prefix, nothing trailing
inline `[M:]` at the head of a line  -> the PREVIOUS line's end, nothing in the prefix
standalone `M:` after a `\`          -> INLINE, where it stands            <- THIS
```

We draw nothing for it. The suspicion, not verified: our parser sends every standalone `M:`
through `setMeterForNextLine`, which parks it for `beginMusicLine`; if a `\` continuation
suppresses that call the meter stays parked until the NEXT line, where X:812's own `M: 6/8`
overwrites it and the 9/8 is lost outright. Check whether the parked meter survives a
continuation before changing anything — and note `meterChangeLeadsLine` is NOT what suppresses
it, since that needs `meterChangeInline`.

Closing it also closes the `ox` -3.16 raise recorded against this tune, which is a mean over
exactly this step.

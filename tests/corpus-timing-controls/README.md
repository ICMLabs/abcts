# Timing control tunes — abcjs's answer for tunes abcjs's suite does not contain

Generated by `node scripts/gen-timing-controls.mjs`, which renders each tune with abcjs
itself and records what `setTiming(bpm, measuresOfDelay)` returns. Same file shape as
`tests/corpus-timing/`, read by the same ranked table under the same ratchet.

**They are here rather than in `corpus-timing/` because `npm run harvest:timing` clears
that directory.**

## Why controls exist at all

`timing.test.js` warps two tunes twelve ways, and both tunes are 4/4 with no pickup, one
voice and no mid-tune tempo. So whole branches of `setTiming` had no case behind them, and
the one that named this ladder is `startingDelay -= getPickupLength() / beatLength /
beatsPerSecond`: **deleting that line outright left the harvested table at 0 of 13.** A line
no case can reach is a line no gate can defend.

Twenty-five rungs, one variable each: the count-in with and without a pickup, all three arms
of `getBeatLength` (6/8 and 9/8, 3/8, 5/8 and 7/8), the 180-or-120 default, a stated beat
unit that is not the beat, a mid-tune `[Q:]` both plain and warped, the repeat walk with
and without endings, two voices ragged and level, a spacer and a triplet.

`plain` is the CANARY — a bare 4/4 tune at its own tempo, which every other rung must differ
from.

**And the ladder found one on its first run.** `repeat-endings` gave 21 rows against abcjs's
17: `startEnding === '1'` is what stops the replay before the first ending, and `|1` is ONE
element in abcjs where our model splits it into a barline and a volta on the measure after
— the same split the chord grid hit, load-bearing here for a different reason.

# Audio control tunes — abcjs's answer for tunes abcjs's suite does not contain

Generated by `node scripts/gen-audio-controls.mjs`, which renders each tune with abcjs
itself and records what `setUpAudio(options)` returns. Same file shape as
`tests/corpus-audio/`, read by the same ranked table and held to the same ratchet.

**They are here rather than in `corpus-audio/` because `npm run harvest:audio` clears
that directory.** These are not harvested from anything; the tunes are ours and only the
answers are abcjs's.

## Why controls exist at all

`options.test.js` exercises `drumIntro` twice, both times the same way: one intro measure,
no pickup, 4/4, one voice. Every other branch of the splice
(`abc_midi_sequencer.js:510-537`) had no case behind it — the `drumIntro-1` loop, the
pickup coming out of the last intro measure, that measure getting no barline, a count-in
on a tune with no drums, and `measureLength` being whatever the tune's LAST `M:` left
behind. Code with no case behind it is where this repo has found most of its defects.

**The corpus is not the oracle, it is a sample of it.** abcjs renders any tune on demand,
so a finding blocked on "nothing does this" is blocked on nothing.

`intro-0` is the ladder's CANARY: the same tune and the same drum with no count-in at all.
Its voice starts at 0 where `intro-1`'s starts at 1 — if the gate cannot tell those apart
it is not measuring the axis.

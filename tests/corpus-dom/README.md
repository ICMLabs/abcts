# abcjs DOM-contract corpus — the `class` and `data-name` tree

Generated by `node scripts/gen-dom-contract.mjs` (`npm run gen:dom-contract`), which renders
each tune with abcjs itself under `add_classes: true` and records every element carrying a
`class` or a `data-name`, in document order, with its DEPTH.

## Why this axis had no instrument

`pixel-parity` and the harvested table resolve both SVGs to ABSOLUTE PIXELS and compare
positions — they throw the markup away on purpose, because that is how they see past
`<rect>`-versus-`<path>` and Bravura-versus-abcjs outlines. The structural gate compares
abcjs’s LAID-OUT ELEMENTS, which are its internal tree and not its output.

So the thing a drop-in replacement is actually judged on — does
`querySelector('[data-name="note"]')` find a note, and is it inside the group a host expects
— has never been measured here. The 2026-08-09 suite audit corrected an earlier reading to
say exactly this: `visual/svg.test.js` and `svg-per-line.test.js` assert the DOM contract,
not the internal tree, and eight cases were nearly written off as unportable.

## What is compared, and what is not

Compared: `class`, `data-name`, and DEPTH — so grouping is part of the contract and not just
membership.

**Not compared: the tag name.** A staff line is a `<path>` in abcjs and a `<rect>` here, a
drawing choice `pixel-parity` already proves equivalent. Folding it in would drown the axis
this gate exists for.

## The tunes

`svg-*` are `visual/svg.test.js`’s own three. The other twenty-two are controls, one feature
each, because that file covers a clef, a time signature and a note and nothing else — and a
contract is exactly the kind of thing that holds for the features someone tested and lapses
for the ones they did not.
